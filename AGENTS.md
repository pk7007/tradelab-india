# TradeLab project review workflow

## Autorun within authorized scope

For a clear project task or master prompt, begin execution and continue through
inspection, implementation, suitable tests, independent review, fixes and rechecks.
Resolve routine reversible implementation choices using the existing request,
saved decisions and repository conventions. Do not repeatedly ask whether to
continue or ask the user to perform a step the agent can carry out.

Recover from diagnosable failures within scope. Continue independent work while
a required input is missing. Finish with the delivered result, verification,
review score, material limitations and any specific remaining user action.
Produce outstanding work through concrete acceptance criteria and evidence.
Describe unverified outcomes honestly, including any score below the target.

Prior authorization carries across related steps and reviewer rechecks. Autorun
does not expand scope or grant new authority over funds, credentials, external
messages, destructive changes or paid services. Follow applicable tool approval
requirements. Ask only for a material unresolved decision, a necessary unavailable
input, or an action whose approval is required. Interactive Zerodha login stays
with the user. Respect the deferral of market-dependent activation until Monday,
23 November 2026.

These are coding-agent execution instructions. They do not enable unattended
broker orders or imply that a background Codex agent is permanently running.

The user requests a review subagent after each completed project task, including
implementation work and reusable master prompts or plans. Use one independent
reviewer for each meaningful deliverable. Batch closely related edits into one
review. Keep short factual conversation answers concise.
The assigned reviewer reports to the lead agent and does not delegate another
review of its own review. Reuse the same reviewer for repair rechecks.

## Required review cycle

1. Establish the user's requested outcome and concrete acceptance criteria.
2. Complete the authorized implementation or draft.
3. Assign an independent Codex subagent to inspect the resulting deliverable,
   relevant callers, tests and evidence. For prompts, review scope, dependencies,
   feasibility, acceptance tests and permission requirements.
4. The reviewer reports actionable findings by severity, evidence and a score.
   Score correctness, integration, resilience, verification and usability from
   zero to two each, for a total out of ten. Explain deductions. Use N/A for
   unobserved performance and profitability.
5. Fix confirmed issues within scope and run appropriate regression checks.
   Ask the reviewer to recheck changed areas until the evidence supports at least
   nine out of ten with no unresolved critical or high-severity issue.
6. If a prerequisite requires live data, provider access, user input or a scope
   decision, report the remaining gap and actual score. Keep deferred market
   tasks deferred. If repeated reviews produce no justified actionable change,
   document that limit and the next useful verification.
7. The final response states the review outcome and material remaining limits.
   A desired score must never become a fabricated result or trading guarantee.

## Trading agent integration requirement

Route each trading-process task to relevant implemented roles from the shared
registry, with a separate reviewer and explicit evidence handoffs. Cover market
research, discovery, data validation, issuer/event mapping, strategy signals,
risk, sizing, paper execution, reconciliation, reporting and improvement.
Use one lineage linking input versions, availability times, task IDs, findings
and downstream decisions. Block dependent work when required evidence fails.
Research or review failure may block new entries. It must preserve existing
deterministic risk controls, protective exits, exposure reporting and ledger
reconciliation. Optional research outages must not suspend required exit processing.
Run periodic reviews for active workflows and reviews on new task results.
Only schedule roles with the required inputs and working handlers.

The full runtime integration is a recorded requirement. Existing monitoring and
automatic selection implement a subset. Consult docs/agent-integration-requirements.md.
Code review scores cannot authorize broker orders, strategy promotion, changed
loss limits or automatic changes to a running strategy. Use existing authorization
and operational controls.
