# TradeLab gap audit and repair — 20 November 2026

## Owner briefing

The local prototype has improved failure handling, but it is not a 9/10 continuous trading service. This audit started with 189 passing Python tests and ended with 202. Separate execution, news and frontend reviews reproduced new defects; fixes and regressions are detailed below. The broker live readiness gate remains closed. No new provider credentials, live orders or publication were used. Existing accounts and the unrelated college attendance project were preserved.

The shortest path forward is a bounded one-account completed-candle paper scheduler using the existing broker subscription, a verified session manifest and explicitly confirmed data retention. Buying another API does not solve the missing execution/ownership/scheduler integration. Long-term recommendations and profitable strategy promotion remain unsupported by the required evidence. See the [external-source procurement plan](external-source-plan.md) for current provider references and costs.

## Architecture: where authority really resides

| Journey | Actual implementation | Boundary |
|---|---|---|
| Browser → request | Loopback Host checking, CSRF for mutations, bounded JSON, server validation | Local single-user trust; no public deployment/multi-user authentication certification |
| Login → account | In-memory token/profile; callback updates under shared lock; bounded idle sessions | Restart clears login; token presence is not broker readiness |
| Manual review → intent → evidence | `app.py` + `ExecutionJournal`: session-bound review, persisted submission, exact broker order/trade checks | Dispatch blocked; no authoritative net-position ownership/funding link |
| Strategy config → mock submission | `Coordinator` + shared funding tables: transactions, reservations and mock lifecycle | Different ledger from manual/paper; running/pause state process-local; no production adapter |
| Candles → paper | `PaperEngine` + opt-in `intraday_contract`: ordered imports, completed-close signal, modeled fills, ledger | Independent simulated capital; OHLC participation is an assumption, not executable order-book liquidity |
| Evaluation → research evidence | Fixed daily evaluator, experiment history, exact-engine intraday replay | No point-in-time universe, independent strategy edge, matched intraday benchmark or verified forward observations |
| NSE RSS → research context | In-memory reader, exact loaded NSE EQ name mapping, availability cutoff | Browser/request driven, rolling feed, no guaranteed revision/completeness service; first-seen resets on restart |
| Moneycontrol → cache | Injected mock transport, SQL cache/revision logic | Private URL/key/client ID absent; pagination and corrected-item retrieval unclear; no running retention daemon |
| Model output → evidence schema | `evidence.py` rejects unknown control fields and validates citation/time schema | No AI provider connected; schema checks do not establish semantic truth |

No component converts all three ledgers into one real broker-funded portfolio. Delayed licensed snapshots must not enter executable-price decisions. The three main tabs simplify navigation without changing these authority boundaries.

## Intraday model findings

The opt-in model sizes whole shares including supplied costs, caps planned downside against remaining daily allowance, processes exits while entry-paused, uses a stop-first assumption for ambiguous OHLC, and retains shares on insufficient modeled participation. Existing tests cover gaps exceeding ₹25, both stop/target crossings, zero volume, halt/reject flags, partial exits, missed square-off, carried recovery, restart and protection drift.

Daily loss is modeled equity decline at observed opens/closes; it is not a guaranteed intrabar maximum. Share/participation caps and slippage remain user assumptions. No real order IDs are assigned by the OHLC engine. Legacy models permit overnight shares. Missing same-session candles reject ingestion instead of fabricating recovery/fills. These are material boundaries even when the financial journal matches.

No strategy was optimized in this audit. Existing synthetic SMA evidence remains unrelated to real Indian equity profitability. The exact-engine intraday replay still has no independent holdout/benchmark promotion certification. Rejected strategies and prior weak results remain in the repository; no acceptance threshold was moved to make them pass.

## Operating and incident guidance

Use the main loopback app with private `.env`; do not paste tokens into chat. Restarting loads changed Python code and clears broker login. Keep live flag false; server readiness gate must remain closed. The audit preview at port 8778 has blank credentials and temporary ledgers. See [existing setup/recovery guide](system-repair-2026-11-18.md) and [intraday operations](intraday-readiness.md).

Unknown/conflicting order: pause new actions, inspect every broker identity directly and preserve the journal. Normal polling intentionally cannot clear a multi-ID conflict; no unsafe force reset was added. Missing reservation: restore/reconcile accounting evidence before resolving an intent. A balance green check is not proof of portfolio ownership.

Feed failure: mark evidence stale, exclude it from current research, recover in order, and never fill missing prices. Licensed revision failure/full-page uncertainty: stop serving cache, retain no withdrawn article text, investigate actual pagination and purge derivatives/backups. SQL secure deletion is not a forensic SSD/backup erasure guarantee.

Paper incident: inspect actual model, exposure, pending exit, daily halt and protection. Pause new entries preserves exit eligibility; stopping ingestion freezes prices and leaves shares held. No software pause/close request guarantees a real broker action. Restart requires explicit review/resume.
