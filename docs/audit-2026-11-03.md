# TradeLab application audit — 3 November 2026

Scope: current application screens, account presentation, order review, local API trust boundary and offline execution prototype. This is a software audit, not a profitability study or certification. No live trades were submitted.

## Fixed findings

- Account position view used day records ahead of net records. It now uses net positions, and the P&L total includes closed net positions. Renamed the metric to net position P&L to avoid claiming account-wide daily profit. Basis: [Kite portfolio documentation](https://kite.trade/docs/connect/v3/portfolio/), retrieved 2026-11-03.
- Older asynchronous responses could overwrite a newly selected screen. Request generations now discard stale account responses; all account summary components use the same refresh batch.
- Disconnected account screens retained stale tables/totals and inappropriate titles. Clear state and explicit empty/error messaging added.
- Account button had no disconnect action; it now disconnects the broker session, while refresh also updates automation status.
- Manual submission generated new IDs on retries. Server-issued confirmations now bind the exact normalized order and expire after 120 seconds. Consumed confirmations cannot be replayed. Ambiguous errors require broker-order review rather than retry. This remains in-memory session protection, not cross-restart broker reconciliation. See [Kite order lifecycle](https://kite.trade/docs/connect/v3/orders/), retrieved 2026-11-03.
- Confirmation button was prematurely enabled and changes to the order form did not invalidate the review. Fixed; edits hide the old review and quote.
- Numeric JSON quantities could be truncated from fractional numbers, and boolean quantities were accepted. Both now rejected. Stop-limit direction is checked.
- Added loopback Host validation against DNS-rebinding requests. Origin and CSRF checks remain required for mutations. Standard broker HTTP 403 clears its expired account session.
- Mock dispatch now rechecks reconciliation and rejects intents from obsolete strategy versions.
- Improved narrow-screen form columns, table scrolling, keyboard focus visibility, heading wrapping, dark select contrast and India-time date labels.
- Broker connection indicator no longer appears live while disconnected; fetch requests have a 20-second timeout.

## Verification

- 52 Python offline tests passed with scripts/check_research.py, including 6 new order/host regression tests. Test broker is mocked; app definitions loaded without credentials or network setup.
- Node account regression verifies net/day separation, inclusion of closed-position P&L and empty data handling.
- Python compile and JavaScript syntax checks passed.
- Browser navigation checked for all seven screens: Automation, Overview, Orders, Holdings, Positions, Market data, Strategy lab. Account screens checked disconnected, not against a live authenticated portfolio.
- Browser stress lab rendered 24 rows; synthetic strategy run returned results; ranking without loaded history displayed the missing-data message. No browser console errors observed in those flows.
- Narrow current browser viewport checked visually. Exhaustive device/browser compatibility has not been tested.

## Remaining limitations

Production automated execution, live scheduler, automatic exits and broker reconciliation are still unimplemented. Financial settings remain unapproved. Real order execution, authenticated account accuracy, live streaming, download coverage and session-expiry behavior against Zerodha were not exercised. Synthetic results do not establish profitability. Historical research lacks verified corporate actions, point-in-time fundamentals, historical membership and complete tax/fee modelling. Do not interpret this audit as making unattended trading ready.

Local HTTP checks passed for untrusted Host rejection (403), missing CSRF (403), invalid configuration (400), disconnected positions (401), and serving all JS/CSS assets. No order endpoint was called in these runtime checks.
